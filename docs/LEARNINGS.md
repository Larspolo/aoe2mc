# Learnings

The agent writes here what it learned the hard way. Each line must save time in a later session.
Ticket runs: add new lines at the end of a section and do not change other lines (`merge=union` in `.gitattributes`
keeps the lines of both sides). A pitfall of one topic goes into the "Pitfalls" section of its document (list below; add
at its end, do not change other lines): this file loads into each turn of each run. The `improve` skill merges lines,
and `tests/test_learnings.py` fails above 80 lines (#1698).

## Environment and libraries

- Pitfalls of one topic: the Minecraft server, client and NBT (silent defaults, dropped tags): `docs/minecraft-versions.md`; Paper, the game program, its menus (`train.TRAINS`, slots), `combat` tables and AoE2 values from the wiki (infobox, availability chart): `docs/research/gameplay.md`; RCON `@e`, datapack items: `docs/datapack.md`; records (`mgz`, test records, offline replays): `docs/research/replays.md`; bundles (Tk, artifacts, `appimagetool`): `docs/packaging.md`; water terrain: `docs/research/water.md`; designs (cylinders, furniture, renders, shelf items, rooms): the `design` skill.
- GitHub raw files, PyPI, the Mojang hosts, `minecraft.wiki`, `minecraft.net` and the record API `api.ageofempires.com` work (`docs/ENVIRONMENT.md`). Blocked: the AoE2 wiki HTML (a Cloudflare challenge: use `tools/refimage.py`, MediaWiki API), `data.aoe2companion.com` and `www.aoe2insights.com` (a Cloudflare 403).
- Minecraft 26.3 (the default) needs Java 25 (`scripts/cloud-setup.sh`, #195). Send `stop` only after "Done (" is in `logs/latest.log`. A `&` job ignores SIGINT: test Ctrl-C with `Popen(..., start_new_session=True)` and `os.killpg(pid, SIGINT)` (#137).
- GitHub in cloud sessions: `gh api repos/Larspolo/aoe2mc/...` (REST) works. GraphQL (`gh issue list`, `gh pr create`), `search/...` and branch deletes give 403. A push to a new ref works, a non-fast-forward push fails: `tools/claim.py` uses it as a lock (#211). REST ref paths: `git/refs/heads/...`. `urllib` with a JSON body needs `Content-Type: application/json`, else 415 (#345). The clone is shallow: `git fetch --unshallow origin` before a scan of the history (#367).
- `tools/claim.py` names the run by the current local branch (`who()`): run each call (claim, beat, guard, release) on the branch that pushes the ticket (the session branch, or `<session branch>-<k>` for a later ticket, `more.md`), never in parallel (#361); a claim made on a local branch `t1668` belongs to "t1668" (#1668). A beat while you work on a local branch: `git worktree add $SCRATCH/wt <session branch>` once, then `cd $SCRATCH/wt && python3 tools/claim.py N --beat` (#1643). Run `claim.py N` and `claim.py N --guard` each in its own tool call and read the exit code first: in parallel calls the label and "Started by" run also on exit 1 (#965), and `guard; echo g=$? && git push` pushes after a failed guard (#540). It fetches, so it overwrites `FETCH_HEAD`: fetch a `checks/N` ref into a named ref (`git fetch origin +refs/heads/checks/N:refs/remotes/origin/checks/N`) before you build its next commit.
- Wait loops: ruff prints "All checks passed!" first: wait for an `echo rc=$?` line (#1243). `pytest` ends with one result line also with `-q` ("N passed (exit 0)", `tests/conftest.py`, #2510): read it, do not run the suite again. Foreground `sleep` is blocked: `run_in_background`, then `timeout 580 bash -c 'until [ -s OUT ]; do sleep 5; done'` (#413, #514). `rm -f OUT` before a second run, else the loop reads the old file (#738).
- `mcp__github__get_job_logs` with `job_id` and `return_content: true` works for `ci.yml` jobs (2026-10-27, #1710; it gave 404 on 2026-10-26, #443): read the failed tests there, then run them locally on the run's `head_sha`.
- `-m mc` needs `javac` and `xdotool` (setup script, #493, #638); without `xdotool` it skips `tests/test_menu_client.py`. The full `-m mc` suite takes hours: CI runs it in 6 shards (#1710). Run only the `-m mc` files that use the changed code (`grep -l "aoe moveto" tests/*.py | xargs grep -l mark.mc`) in the background (#1669).
- AoE2ScenarioParser 0.9.8 makes new scenarios (`tools/scenarios.py`: `new_scenario`, `add_unit`, `save`). It prints much text (`redirect_stdout`), default players are RANDOM (`western`), `write_to_file` writes the output file name into the file (same bytes: `scenarios.save(..., name)`, #204), and it refuses to write over the file that it read: read a temporary copy (`scenarios.triggers`). No scenario in `examples/` and `samples/` has triggers: use the `triggers` scenario (#646).
- Images of a check ticket or a PR: push an orphan commit (`git mktree`, `git commit-tree`) to `refs/heads/checks/N` and link `https://raw.githubusercontent.com/Larspolo/aoe2mc/checks/N/NAME.png` (#614). A second check: build the tree from the old tree and the new files (`git ls-tree OLD` piped into `git mktree`), else the old image links break (#718).
- Same output of a conversion: compare two worlds with `tools/world_diff.py A B`. `diff -r` and `cmp` always differ: the .mca time tables, gzip headers and `LastPlayed` hold the time (#702).
- The auto mode denies the close of an issue (a finished epic #862, an answered decision ticket #1323, an answered check ticket #1641), the no-code PR that closes an epic ("Auto-Mode Bypass", #842), a skill edit around a denial ("Instruction Poisoning", #971), a tag push `v*` ("Create Public Surface") and the run of a downloaded binary (#1542, #1608). Never send it another way: comment the evidence of each criterion, then add the label `close` (`close.yml`, autopilot `owner.md`, "Close an issue", #1740). For a decision ticket, also write the decision into the body of the waiting ticket and remove it from its "Depends on:" line.
- Automerge takes the first "close #N" (also "fix", "resolve") anywhere in the PR body as the ticket, also in "does not close #N": a ticket with `needs-human` then stops the merge (#984). Do not write those words before another issue number. It waits only for `quick`: a PR that changes `packaging/` or a workflow with its own PR checks gets `hold` until they pass (#1599, #1541).
- A check ticket that waits for a fix: `git fetch origin main && git checkout -B <branch> origin/main` just before the level-4 run, and name the commit in the result (#964). A check that finds a bug: read `git log origin/main --oneline -15` and the open issues for the symptom first (#1249 was a copy of #1219, #1256).
- A background `-m mc` run imports the code of the working tree: do not `git checkout` another branch there until it ends (#1664 tested main's `units.py` for 10 minutes). Do the next ticket in a `git worktree`.
- Wait for a background command by the task ID of its own result: a typed file name from an earlier task waits the full 580 s for nothing (#2342, #2357).
- The refill lock `claim.py 0 --refill` does not lock an epic: run `claim.py E --refill` for each epic E before you make its sub-issues, and list its open sub-issues again just before. A parallel run made 4 of the same trigger tickets in the same minute (#2612 copied #2609, #2621 copied #2611).
- The clone of a session can hold an `origin/main` of days ago: `git fetch origin main` before `git checkout -B <branch> origin/main`, also for a check ticket. #2278 measured a replay on a main of 2 days ago (`git log -1 --format=%ci`) and found a false regression.
- Blocked too: `docs.racket-lang.org` and `plt.cs.northwestern.edu` (the docs of the AoE2 random map script DSL, DNS fails). For a random map script fact, a `WebSearch` summary of them works (#3966).
- A `git checkout -b agent/N-...` after `claim.py N` makes the next beat name another run: `claim.py N --beat` then says "took #N over" (#4134). Work on the session branch, or move the changes with `git stash -u`, `checkout -B <session branch> origin/main`, `stash pop`.
- The Blacksmith pages (`aok.heavengames.com`) work, but `getfile.php?id=N&dd=1&s=TOKEN` (TOKEN from `get_file(...)` of `showfile.php`) redirects to `files.heavengames.com`: blocked until the owner pastes `scripts/allowed-domains.txt` (#4189).
- A later ticket of a run (brief or not): `git checkout -B <session branch>-<k> origin/main` before `claim.py N --adopt CLAIM`; the claim takes the branch name of the call. After the wrong order, `claim.py N --adopt <old branch>` on the new branch moves it (#4240).

## Code

- AoE2 map orientation (#23): tile (0, 0) is the left corner of the screen, (max, 0) the top. Block x = east, z = south: the world is turned 45°, not mirrored; the AoE2 top corner is in the north-east (`SPAWN_YAW`). Do not trust the axis gate names: `plan_walls` uses the walls next to the gate. `--orientation` turns the tile grid (`turn_map`) and each building canvas (`buildings.turn`); gates, walls and bridges follow their neighbours.
- Real maps have all water at elevation 0 (#164). `terrain_style`: an earlier rule wins (#5). `columns()` in `tests/test_terrain.py` makes `Columns` from a terrain array. Maps of one size draw the same random numbers.
- `place_objects` without a scenario: one object dict (`kind`, `name`, `player`, `x`, `y`, `rotation`, `hero`, `garrisoned`) on a 16 × 16 `Columns`. Buildings (also `FISH_TRAP`, docks) need `kind="B"`. `build_chunk` returns `(nbt, vol)`: test exact blocks with `vol` (#19). Footprint rule: `Edits.add` keeps a block outside the footprint when `y >= cols.wtop + E.HEAD`. Match a block by its name before `[` (`water_cauldron` starts with `water`, #295). A `MONUMENTS` object goes to `place_building` as a copy without `o["footprint"]`: use `buildings.footprint(name)` (#296). `place_objects` tests `"FLAG" in name` before `units.invisible(name)`: name an invisible object `INVISIBLE_OBJECT` (#772).
- A new runtime data file (like `tools/mcdata/26.3.json`) must go into the package data (`pyproject.toml`).
- Generated on main, not in PRs: the column "Used today in" of `docs/DESIGN.md` (`tools/feature_table.py`), `docs/coverage.md` and `MAX` in `tests/test_coverage.py` (`coverage.yml`, #233, #234). A conflict there: take main's side. `docs/coverage.md` can be stale (#460): for the real fallbacks run `python3 tools/coverage.py OUT.md` into the scratchpad (#500).
- Block IDs in `B` depend on earlier tests: draw random numbers in state-name order, not ID order (a cause of full-suite-only failures, #44).
- `aoe2mc.json`: object kind is `"unit"`; `"id"` is the AoE2 type constant, the object ID of a record is `"ref"` (#408). The "ground" of a blocked footprint is the barrier top: take the free cells of `Map.around()` (#307, #391). Stump names: `STUMP`, `*_STUMP`. The `buildings` scenario: building i of `BuildingInfo` is near tile (4 + i % 40 × 7, 4 + i // 40 × 7).
- Parallel sibling tickets: before you add a helper or a tool option, `git fetch origin main` and grep for it (two runs added a `furnish()`; the second broke main, #263). Before you write a new test file, `ls` its name: a ticket can name one that exists (#1147).
- "units in a block": `AOE2MC_DEBUG=1` names the block; list the `aoe2mc.json` objects with a `tile` near the unit to find its source (#415: a `PLANT_SHRUB` on the same block, not the tree that the ticket named).
- A gate footprint is not in `cols.blocked` (units walk through the passage): `place_building` blocks only the columns with a solid block at head height (#577). Reproduce "units in a block" of a campaign with `tests/test_scx.py` `build()` and random units on the wall line. With a step under a gate, the foundation lifts the passage floor: `buildings.FLOORS` holds the stand height (#773); a slope: `elevation` in `build()` (`tests/test_scx_walls.py`).
- A change to the blocks of an object: also run the `-m mc` tests of the files that name it (`grep -l NAME tests/`): the fast suite skips them, and #590 broke `test_villager_forages_on_a_server` (fixed in #602).
- A merge conflict between two new code blocks: do not join the two sides by a script. A hunk can cut through a block (#517: the Java of the plugin did not compile). Apply your change again on main's file, then build.
- `[f"...{o['id']}"] * ("id" in o)` evaluates the f-string also when the factor is 0 (KeyError): use `o.get('id')` in it (#681).
- `git stash` and `git stash pop` (or a `sed` edit) can give a file of the same size in the same second as its `.pyc`: Python then runs the old `.pyc`, and tests fail with the old values. Delete `game/__pycache__` (and the others) after a stash before the tests (#1551).
- `game/data/*.jsonl` merge by name with `tools/merge_jsonl.py` (`merge=jsonl`, #2004; the SessionStart hook registers the driver): a name that both sides changed is a conflict, take main's line and run the change again. "more than one line for X" after a merge: `git config --get merge.jsonl.driver` is empty: run `.claude/hooks/session-start.sh`, then fix by `diff <(git show origin/main:FILE) FILE` (#1890, #1934, #2010).
- A new check over the whole code (a lint with a list of known cases) can turn main red: PRs that merged after its CI run add new cases (#2026: `ARCHER_LINE`, `LONGSHIPS`, fixed in #2061). After the merge of such a check, read the next CI run on main.
- `tools/data_lint.py` also counts the names in an f-string inside a list literal (`[text(f"...{d['CASTLE']}...{d['WONDER']}")]`, #2034).
- A fix of red main that open PRs port (CI rule "port the fix") merges once per PR: two versions of it can stay side by side with no conflict (#2131: `TWO_TYPES` twice and `MIXED` in `tests/test_data_files.py`). Before you push a "Fix main" PR, `git fetch origin main` and read the file again: main can have the fix already.
- Two ready tickets can ask for the same feature with other words (#2357 `--victory regicide`, #2347 `--mode regicide`): before the code, `git log origin/main --oneline -10` and the open tickets of the same epic; fetch main again before the push (#2387 merged #2347 while #2357 was coded).
- The `texts` dict of `read_scenario` holds the message chapters (`CHAPTERS`: `book_pages` reads `"victory"`, `"loss"` as text): a new key needs a name that is no chapter key (#2566 used `"global_victory"`).
- A ticket's Context can name a behaviour that the code lacks: #3377 said that `save` wrote the game time, but no save had one. `grep` the function before you build on the Context. A field that a function sets on `g.game` (not on a Gather) is not seen by `tests/test_savegame_fields.py`.
- `docs/triggers.md` cannot be regenerated from a test scenario: `tools/triggers.py --doc` counts the files it gets, so a `triggers` scenario alone rewrites its file list and 136 rows (#3775). Edit its one row by hand, or regenerate it from the full file set of CI.
- A list of AoE2 building names in code (`("LUMBER_CAMP", "MILL")`) fails `test_game_names_in_code.py`: take them from the data, for example the `building` of the rows with a `line` key (#3790).
- A new `convert()` keyword must not be named `players`: `convert` unpacks its own `players` (the player dict), and ruff reports F821 at the call (#3945: `nplayers`).
- A "Damage Object" effect with no type and amount 0: `damage_lines` reads `e["object"][1]` on the building path, so `object` must be a tuple, not None (#4073 test: `(None, None)`).
- A test that lists the castle items of the default civilization (`tests/test_trebuchet.py`) breaks when a unique technology of that civilization joins the list: filter the new name, do not change the civilization (Franks have their own units, #4103).
- A field set with `vars(g).setdefault(NAME, ...)` on a Gather hides a method of the same name: `ruins.fall` set `g.fell` (a list) and the next felled tree stopped the game (#4147). `grep -n "def NAME" game/gather.py` before you add a field.
- `tools/claim.py N` succeeds for each N it gets: a loop over several numbers claims all of them (#4132 run took 4 by mistake). Call it once per ticket, and read exit 0 before you work on it.
- A test of a building with `footprint` in aoe2mc.json uses `[x0, z0, x1, z1]`, but `homes()` and the test constants of `(x0, x1, z0, z1)`: a castle at `(8, 12, 8, 12)` put into the data gave no menu (#4337). Write the data order by hand.
- A test that patches a data table of a civilization key (`civs.BY_KEY`) must patch the plain `civs` too: `game/monk.py` imports it by its plain name, so a patch of `game.civs` alone changes nothing (#4447, as `tests/test_techs_saxons.py`).
